# Operations

## CockroachDB bootstrap (one time, or when re-keying credentials)

The cluster is `aqua-roach` (CockroachDB Cloud), database `school_intelligence`.
This cluster may host more than one application; the bootstrap script only
ever touches the `school_intelligence` database and its own three SQL users.

1. In your own shell (not through any chat tool), set the admin connection
   string transiently:
   ```bash
   export COCKROACH_BOOTSTRAP_URL="<admin connection string for aqua-roach>"
   ```
2. Run the bootstrap script:
   ```bash
   ./scripts/bootstrap-cockroachdb.sh
   ```
   This verifies TLS, runs `SELECT 1`, checks current privileges, creates
   `school_intelligence` if it does not already exist, creates
   `school_migrator` / `school_ingestor` / `school_app` with generated
   passwords (never printed), applies least-privilege grants per
   `docs/database.md`, and writes the three resulting scoped connection
   strings directly into GitHub secrets and Vercel environment variables via
   the `gh` and `vercel` CLIs.
3. Unset the bootstrap variable:
   ```bash
   unset COCKROACH_BOOTSTRAP_URL
   ```

## Free-tier calibration

Before any import beyond the pilot scope, the ingestion pipeline records
cluster storage and compute usage before and after a bounded pilot import
(10,000 representative schools, trust relationships, a selected set of
metrics, and catchments for the Sheffield pilot), then projects full
national-scale usage with a 30% safety margin. See the calibration report
generated by `scripts/calibration-report.md` (populated after the first real
pilot import; do not treat a report as valid if it predates the current
schema or source list).

A larger import than the calibrated pilot does not start without an explicit
go-ahead based on that report.

## Data retention

Handled by `ingestor cleanup`, scheduled as part of `ingestor run`:

- Expired `PostcodeCache` rows
- Superseded `CatchmentArea` simplified display geometry for academic years
  no longer shown in the UI (full-detail geometry and source metadata for
  required historical years are preserved)
- Old successful `IngestionRun` rows beyond a rolling retention window
- Any staged/temporary data from a failed import

## Monitoring

`/status` is the operational surface: application status, database
connectivity, latest GIAS import timestamp, latest statistics import
timestamp, catchment source health per configured source, data coverage
summary, and the deployed git commit SHA. It exposes no hostnames, usernames,
connection strings, or stack traces; any underlying error is logged
server-side and reported to the page as a generic status only.

## Incident response

If a scheduled ingestion run fails: check the workflow run in the Actions
tab (linked from the corresponding `IngestionRun.workflow_run_url`), then
`ingestor verify` locally or via manual dispatch against the same
`INGEST_DATABASE_URL` to reproduce. A failed catchment import never
overwrites previously valid boundaries, so a failure here is safe to leave
unresolved for a period without affecting what users see.

If `/status` reports a database connectivity failure in production: check
CockroachDB Cloud's own status page and the cluster's connection limits
before assuming an application bug; free/starter tier clusters have a
bounded connection count, and Prisma's connection pooling settings in
`packages/database` should be checked against that limit.
